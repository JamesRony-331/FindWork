# 管理端登录页与数据大屏设计规格

## 1. 目标与范围

在现有 `admin` Vue 3 + Vite 工程中建立一套成熟、克制、可扩展的管理端视觉与布局基础，本期实现：

- 管理员登录页
- 管端公共布局
- 数据大屏式管理首页
- 登录、退出与路由跳转的前端演示流程

本期数据为集中管理的静态演示数据，不连接或修改后端接口。后续接入数据库时，仅替换数据获取层，不重写页面结构。

## 2. 设计原则

- 保持真实管理系统的信息密度，不设计成营销展示页。
- 用数据对比、状态变化和任务异常建立视觉层级，不依赖装饰效果。
- 不使用紫蓝渐变、玻璃拟态、发光科技风、大面积深色画布或夸张阴影。
- 卡片只用于表达独立的数据单元，避免无意义的多层容器嵌套。
- 所有静态数据均为前端演示内容，代码中明确集中存放，不伪装为真实接口结果。

## 3. 设计系统

### 3.1 色彩

- 主色：深青绿 `#087F7A`，用于主操作、选中态和主图表序列。
- 深色导航：`#093B4B`，用于侧边栏和品牌区。
- 页面背景：`#F3F7F8`，与纯白内容区保持轻微层次。
- 主文字：`#16323D`；次文字：`#647B84`；弱文字：`#91A3AA`。
- 分隔线：`#DCE6E9`，优先使用边框而不是阴影分隔层级。
- 成功：`#138A63`；警告：`#D98B22`；异常：`#C94C4C`；信息：`#397A9F`。

### 3.2 字体与层级

- 使用系统中文无衬线字体栈，不引入外部字体依赖。
- 页面主标题：24px / 700；模块标题：16px / 650；正文与表格：14px / 400–500；辅助文字：12px。
- 数据指标使用 28–32px 的紧凑数字排版，不使用超大标题。

### 3.3 间距与容器

- 以 4px 为基础间距单位，常用间距为 8 / 12 / 16 / 20 / 24 / 32px。
- 桌面端内容区边距 24px，窄屏降为 16px。
- 主要数据面板圆角 10px，输入框和按钮圆角 6px，不使用胶囊形控件。
- 面板使用 1px 浅色边框和极轻微阴影，嵌套区域优先使用分隔线。

## 4. 登录页

### 4.1 布局

桌面端为左右分栏：

- 左侧约 58%，使用深青色背景，展示系统名称、管理端定位和一张由 Image Gen 生成的招聘数据分析抽象视觉资产。文案保持精简，不增加营销式口号。
- 右侧约 42%，纯白背景中心放置宽 380–420px 的登录表单，不再额外包裹悬浮卡片。

移动端隐藏大面积视觉区，保留紧凑品牌标识和单列表单。

### 4.2 表单与交互

- 字段：管理员账号、密码、记住登录状态。
- 密码支持显示/隐藏，输入框有明确的 focus 状态。
- 空值提交时就地显示错误，不使用 `alert`。
- 静态阶段任意非空账号和密码可进入大屏，代码中明确标注为演示逻辑。
- 登录成功跳转 `/dashboard`；退出清除前端演示状态并返回 `/login`。

## 5. 管理端公共布局

### 5.1 侧边栏

- 宽度 224px，可折叠为 72px。
- 顶部为系统标识和“GoWorking 管理端”。
- 菜单顺序：数据大屏、用户管理、岗位数据、采集管理、数据清洗、字典管理、系统日志。
- 本期只开放数据大屏路由；其他菜单保留可识别的“待建设”状态，不伪造功能。

### 5.2 顶部栏

- 高度 64px，左侧为折叠按钮与面包屑，右侧为数据更新时间、管理员信息和退出入口。
- 退出使用页内确认弹窗，不使用浏览器弹窗。

## 6. 数据大屏首页

### 6.1 首屏结构

1. 页头：标题“招聘数据管理大屏”、简短说明、当前静态数据时间。
2. 四个概览指标：岗位数、用户数、待清洗记录、今日采集任务。数据来自静态数据文件，显示“演示数据”语义。
3. 主图表区：左侧占两份宽度的近七日采集趋势，右侧为数据来源占比。
4. 次图表区：热门城市岗位分布横向条形图与数据质量概况。

### 6.2 运行管理区

- 采集任务表：任务名、数据源、最近运行、采集量、状态。
- 最近操作列表：时间、操作人、动作和对象。
- 异常提醒：仅展示静态异常类型和数量，不制造无对应功能的处理按钮。

### 6.3 图表实现

- 使用轻量级 CSS/SVG 图表表达静态数据，不为两个页面额外引入大型图表依赖。
- 折线、条形和环形图保留文本标签与可读图例，不只依赖颜色传达信息。
- 入场动画限于 500–800ms 的图形展开和数值淡入，支持 `prefers-reduced-motion`。

## 7. 组件与代码结构

预期结构：

- `src/router/index.js`：登录与大屏路由、简单前端演示守卫。
- `src/layouts/AdminLayout.vue`：侧边栏、顶部栏和内容容器。
- `src/views/LoginView.vue`：登录界面和前端验证。
- `src/views/DashboardView.vue`：数据大屏页面编排。
- `src/components/`：指标、图表、状态、表格和确认弹窗等可复用组件。
- `src/data/dashboard.js`：全部静态演示数据。
- `src/styles/`：设计 token、基础样式、布局与响应式规则。

`App.vue` 只保留路由出口，页面数据与布局职责分离。

## 8. 响应式与可用性

- 桌面端以 1440px 宽度为主要设计基准，最低支持 1024px 管理界面。
- 低于 1100px 时侧边栏默认折叠，图表区改为单列或两列。
- 低于 720px 时使用抽屉导航，概览指标两列排布，表格可水平滚动。
- 按钮、输入框和菜单均有键盘 focus 状态；图表包含文本标签；色彩对比满足基本可读性。

## 9. 视觉稿与实现流程

1. 使用 Image Gen 生成登录页和数据大屏的完整桌面视觉概念稿。
2. 用户确认视觉稿后，提取实际设计 token 和组件规则。
3. 先实现公共样式、路由和布局，再实现登录页与大屏。
4. 通过应用内浏览器检查桌面和移动端，对照概念稿逐项修正。

## 10. 验证与验收

- `npm run build` 成功。
- `/login` 表单空值验证、密码显隐和静态登录流程可用。
- `/dashboard` 展示完整的静态数据大屏，折叠导航和退出确认可用。
- 不存在浏览器 `alert` / `confirm`。
- 桌面 1440px、1024px 和移动 390px 视口无关键溢出、裁切或错位。
- 对照已确认概念稿检查布局、字体、色彩、间距、图表、图标和交互状态，完成忠实度记录。

## 11. 明确不做的内容

- 不对接后端登录、管理权限或数据统计接口。
- 不实现用户、岗位、采集、清洗、字典和日志的子页。
- 不引入 Element Plus 或新图表库；当后续子页需求明确后再统一评估。
- 不修改客户端和服务端。
