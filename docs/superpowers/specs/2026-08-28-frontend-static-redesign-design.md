# 高校毕业生招聘信息采集分析系统静态前端重设计规格

## 1. 目标与范围

在 `client/Gworking` 内完成公共端和普通用户端的静态前端原型，保持现有 Vue 3、Vue Router 路由及页面文件命名。当前阶段不接后端，不实现管理端；管理端后续由 RuoYi 承担。

本期覆盖 15 个页面：

- 公共端：`/`、`/login`、`/register`、`/profile`
- 用户看板：`/user/dashboard`、`/user/dashboard/charts`
- 就业分析：`/user/analysis/job-demand`、`/salary`、`/city`、`/education`、`/major`、`/multi`
- 岗位：`/user/jobs`、`/user/jobs/:id`
- AI：`/user/ai-chat`

不修改后台接口、`Request.js` 的接口约定或管理员路由含义；管理员页面暂时保留空文件，不进入导航和本期验收。

## 2. 依据与设计方向

功能与字段以以下文档为准：

- `高校毕业生招聘信息采集分析系统_页面功能路由数据来源表.docx`
- `高校毕业生招聘信息采集分析系统_前端页面设计.docx`

视觉基准存放在 `docs/design-concepts/`：

- `public-auth.png`
- `user-dashboard.png`
- `salary-analysis.png`
- `jobs-list.png`
- `job-detail-ai-chat.png`

采用“高校数据研究台”方向：深青蓝导航、浅灰蓝页面背景、白色工作区、紧凑的数据密度、克制的边框和阴影、清晰的中文系统字体。实施时删除概念图中误出现的管理端入口，不照搬生成图中的错误文案或不可用装饰。

## 3. 技术约束

- 使用 Vue 3 Composition API 和现有 Vue Router。
- 仅新增 `echarts` 依赖，不引入 Element Plus、图标库或其他 UI 框架。
- 表单、表格、弹层、分页、导航和状态组件使用原生 HTML/CSS/Vue 实现。
- 图标优先使用项目内统一的内联 SVG 图标组件，不使用文本字符冒充功能图标。
- 所有可重复内容由变量驱动，并通过 `v-for` 渲染。
- 每个页面的数据、图表配置和事件函数放在独立 JS 模块中，由对应 Vue 页面 `import`。
- 演示数据只用于静态原型，后续可将模块中的赋值逻辑替换为接口结果，不改变模板结构。

## 5. 数据模块约定

每个页面对应一个独立 JS 文件，例如 `data/user/salary.js`。模块按页面需要导出：

- `pageMeta`：标题、说明、更新时间等。
- `navItems`、`filters`、`tableColumns`、`tableRows`、`pagination`。
- `summaryMetrics`、`rankingItems`、`detailFields`、`chatMessages`。
- `chartOptions` 或按图表命名的 ECharts 配置。
- `handleSearch`、`handleReset`、`handlePageChange`、`handleSubmit` 等事件函数。

函数不得直接依赖 DOM。筛选函数接收当前状态并返回筛选结果或更新目标；这样后续可替换为异步 API 调用。模板内不放长数组、演示对象或复杂业务表达式。

## 6. 视觉系统

- 主色：深青蓝；强调色：青绿色；辅助语义色：克制的橙色、绿色和红色。
- 背景：浅灰蓝；主内容表面：纯白；边框：冷灰色细线。
- 字号：页面标题 24px，区块标题 16–18px，正文及控件 14px，辅助文字 12–13px。
- 控件高度：36px；表格基础行高约 44px。
- 圆角：控件 6px，主要容器 8px；不使用大胶囊或大圆角卡片。
- 阴影：仅侧栏、顶栏和浮层使用极轻阴影，普通内容主要靠边框与留白分层。
- 页面内容保持紧凑但可读；图表、表格和筛选区对齐到统一栅格。
- 桌面优先；窄屏侧栏收起，图表单列，筛选项换行，表格横向滚动。

## 7. 页面模板

### 7.1 公共页面

首页使用横向导航和两栏首屏，展示系统能力入口，不展示虚构统计。登录和注册采用统一认证表单；个人中心显示基本信息、修改密码和退出入口，静态阶段使用本地表单校验和提示。

### 7.2 看板与分析页

用户看板展示核心指标、趋势、排行与城市信息。独立图表页用于完整展示趋势、Top10 和类别占比。六个分析页共用标题、筛选栏、图表容器、排行和说明区组件，但每页保留文档规定的分析内容与独立数据模块。

### 7.3 岗位页

岗位列表以筛选栏、紧凑表格和分页为核心；静态搜索、重置和翻页在前端变量上可演示。详情页采用定义列表与分隔线呈现字段，不把每个字段包装成卡片。

### 7.4 AI 页面

AI 就业助手提供会话列表、建议问题、消息记录、输入框和发送交互。回复使用本地预设内容并明确属于演示，不模拟真实数据库查询或联网能力。

## 8. 交互与状态

- 导航根据当前路由显示选中状态，并支持移动端收起。
- 筛选、重置、分页、标签切换、密码显隐和 AI 发送均有静态可演示行为。
- ECharts 监听容器尺寸变化并正确销毁实例。
- 表单包含必要的必填、格式和一致性校验。
- 空状态、加载状态和错误状态使用共享组件；静态页面提供可切换的演示状态，但不伪造后端错误。
- 所有按钮提供 hover、focus-visible、active 和 disabled 状态。

## 9. 验证与验收

- 安装依赖后运行 `npm run build`。
- 使用应用内浏览器启动项目并逐个访问 15 个路由。
- 检查桌面首屏、窄桌面和移动宽度。
- 验证导航、筛选、重置、分页、表单校验、详情跳转、AI 本地发送及图表缩放。
- 对照五张概念图检查配色、字体、间距、密度、表格、图表、导航和容器模型。
- 记录至少五项视觉对照点和修复结果；最终用 `view_image` 同时检查设计概念与最新浏览器截图。
- 确认模板中没有硬编码的重复演示列表，页面数据和函数均来自独立 JS 文件。

## 10. 明确不做

- 不实现管理员端页面。
- 不接入后端 API、鉴权或真实 AI。
- 不安装 Element Plus 或其他 UI 框架。
- 不新增管理功能、虚构业务字段或改变现有路由语义。
- 不使用渐变、玻璃拟态、卡片墙、夸张阴影、巨型标题或装饰性动效。
